# 01 算法与定点推导

## 1. 输入与帧结构

| 项 | 值 | 来源 |
|---|---|---|
| 采样率 fs | 10 kHz | `CUR_SAMPLE_FREQ` |
| 采样位宽 | 24 bit 有符号 | `DATA_WIDTH` |
| 通道数 | 4 | `MAX_CHAN_NUM` |
| 每帧点数 N | 256 | `CUR_FFT_POINT` |
| 帧间隔 | 25.6 ms（39.06 帧/s） | 256 / 10 kHz |
| 单边频点数 | 129（0~128） | `FFT_BINS = N/2+1` |
| 频点间隔 | 39.0625 Hz | fs / N |

四路样本由 `mic_collect_top` 的 256 点乒乓缓存给出：`rd_en` 与 `rd_addr` 是唯一读口，`rd_data[0:3]` 在 `rd_en` 后第 2 拍有效（BRAM 1 拍 + 组合广播）。四路共用同一个地址，这是通道间相位可比的前提。

## 2. 加窗

### 2.1 系数

`hanning_256.mem` 存 256 个 24 bit 无符号系数，按对称 Hann 窗生成：

```
w[n] = round( (2^23 - 1) · 0.5 · (1 - cos(2πn / 255)) ),  n = 0..255
```

分母取 255（对称窗），因此 `w[0] = 0`、`w[255] = 0`，峰值落在 `w[127]/w[128]`，实测文件值 `0x7FFEC1 = 8,388,289`（满量程 8,388,607 的 99.996%）。

`hanning_rom_24b` 用 `(* rom_style = "block" *)` 推断为 BRAM，读延迟 1 拍，地址直接接 `rd_addr`。

### 2.2 乘法与截位

`window_oper_24b` 完成 24×24 有符号乘：

```
prod    = unsigned(w) × signed(x)          // 49 bit
prod_hi = prod[46:23]                      // 算术右移 23 位
y       = sat24(prod_hi)                   // ±8,388,607 / −8,388,608
```

右移 23 位而不是 24 位，是因为系数峰值按 2^23 定标；这样满窗系数的增益为 1，不会把满量程正弦压掉一半。截位后必须饱和，否则强信号在窗中心会回绕成反相，直接破坏 PHAT 相位。

## 3. 四路并行 256 点 FFT

### 3.1 IP 配置

`fft_256_wrapper` 内例化 `xfft_256`（Fast Fourier Transform v9.1，Pipelined Streaming I/O，24 bit 输入/输出）。配置字 24 bit：

```
CFG_WORD = {7'b0, SCALE_SCH, fwd_inv=1'b1, 4'b0, NFFT=4'd8}
SCALE_SCH = 8'b1010_1011
```

- `NFFT` 字段是 log2(N)，256 点写 8。
- `SCALE_SCH` 每 2 bit 一段，四段依次为 >>2、>>2、>>2、>>3，总计 >>9。
- `fwd_inv=1` 为正变换；逆变换实例另配。
- 配置通过 `cfg_pending` 保持到 `s_axis_config_tready`，只在帧边界发一次。

### 3.2 为什么是四颗而不是时分复用

旧版分时方案用一颗 256 点 FFT 顺序处理四通道：每通道读 256 点、等 IP 流水、再读下一通道，读口占用约 4×256 = 1024 拍，且四通道频谱不是同一时刻的快照。四颗并行后：

- 读口只占 256 拍，四通道同拍启动、同拍结束；
- 相位关系严格对应同一帧，`tb_fft_chain` 才能用 X1=jX0 这类恒等式逐点检查；
- 代价是 4×24 = 96 个 DSP。

### 3.3 输出与缓存

IP 每拍输出一个频点，`m_axis_data_tuser[7:0]` 是频点索引。调度器只把 `idx <= 128` 的 129 个点写入每通道一块 129×48 bit 的 `freq_bram`（高 24 bit 虚部、低 24 bit 实部）。第 129 点（Nyquist）也保留，供下游按需使用。

## 4. 学习型频点掩码

`freq_noise_mask` 只统计 ch0 的能量，为 129 个频点各维护一个 26 bit 累加器：

```
E(k)   = (re² >> 23) + (im² >> 23)        // 24 bit
pass   = (8 · E(k) > accum[k])            // 当前帧能量高于 3 帧均值的 3/8
mask   = pass && (26 <= k <= 127)
```

- 学习期 3 帧：第 1 帧写入，后 2 帧累加；第 3 个 `frame_end` 拉高 `learn_done`。
- 学习期结束后 `freq_valid_mask` 每帧更新，累加器冻结。
- `restart`（接 `agc_gain_changed`）清空累加器、掩码与 `learn_done`，从头再学 3 帧。
- 频段门 26~127 对应 1015.6~4960.9 Hz，来自实测的麦克风与扬声器可用带宽；带外一律置 0。

注意判据是 `8E > ΣE`，不是“当前能量大于 3 倍均值”。两者相差一个常数因子，改门限时必须按这个式子重算，否则掩码会整体偏松或偏紧。

## 5. 时间预算

| 阶段 | 拍数 | 说明 |
|---|---|---|
| S_IDLE→S_CFG_WAIT | 1 | `mic_frame_valid` 当拍锁存帧号 |
| S_CFG_WAIT | 8 | 等 IP 配置生效 |
| S_CFG_GAP | 4 | 配置与首点的保护间隔 |
| S_DATA | 256 | 四路同址读，`&fft_s_ready` 才前进 |
| IP 流水 | ≈310 | `FFT_IP_LATENCY`，首点进→首点出 |
| S_OUT_WAIT | 0~若干 | 等四路 `m_last` 到齐 |
| S_BURST | 129 | 每拍一个频点，无空拍 |
| 合计 | ≈707 | 14.1 µs，占 25.6 ms 帧预算 0.055% |

整机端到端约 7.2k 拍（含六对互谱与 1024 点 IFFT），本链只占其中约 1/10。因此优化重点不在本链，除非要提采样率或点数。

## 6. 定点误差来源

| 来源 | 量级 | 处理 |
|---|---|---|
| 窗系数 24 bit 量化 | < −140 dBc | 可忽略 |
| 乘加右移 23 位截断 | 1 LSB | 对相位影响 < 0.001 rad |
| FFT 内部 24 bit 定点与 >>9 缩放 | 约 1~2 LSB | 由 IP 保证 |
| 频点非整周期泄漏 | 与窗型和频偏有关 | Hann 窗把旁瓣压到 −31 dB 以下 |

这些误差只影响单帧相位；角度误差还取决于下游 Q10 时延量化与 0.1° 输出量化，不在本 skill 范围内。
